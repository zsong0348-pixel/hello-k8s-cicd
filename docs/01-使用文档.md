# hello-k8s-cicd 傻瓜式使用文档

## 1. 系统如何工作

~~~text
修改 app.py
  -> git push
  -> GitHub Actions 自动测试
  -> 构建 Docker 镜像并推送 GHCR
  -> 自动更新 k8s/deployment.yaml
  -> Argo CD 发现 Git 变化
  -> Kubernetes 滚动更新两个 Pod
  -> 浏览器看到新版本
~~~

日常发布不需要手工执行 kubectl apply。Argo CD 会把 Git 中的配置同步到集群。

## 2. 每次使用前启动和检查

### 第 1 步：启动 Docker Desktop

打开 Docker Desktop，等到显示 Engine running。Docker 没启动时，Kubernetes 和应用都无法运行。

### 第 2 步：打开 PowerShell

普通 PowerShell 即可，不需要管理员权限。

### 第 3 步：选择本地集群

~~~powershell
kubectl config use-context docker-desktop
kubectl get nodes
~~~

预期看到：

~~~text
NAME                    STATUS
desktop-control-plane   Ready
~~~

Ready 表示 Kubernetes 正常。

### 第 4 步：检查 Argo CD

~~~powershell
kubectl -n argocd get pods
~~~

预期所有行都是 READY 1/1、STATUS Running。

### 第 5 步：检查业务应用

~~~powershell
kubectl -n hello get pods
~~~

预期两个 Pod 都是 1/1 Running。

如果不是 Running，执行：

~~~powershell
kubectl -n hello describe pod <Pod名称>
kubectl -n hello logs <Pod名称>
~~~

## 3. 访问应用

### 第 1 步：启动端口转发

~~~powershell
kubectl -n hello port-forward svc/hello-k8s 8081:80
~~~

预期看到：

~~~text
Forwarding from 127.0.0.1:8081 -> 8080
Forwarding from [::1]:8081 -> 8080
~~~

这个 PowerShell 窗口必须一直打开。关闭窗口或按 Ctrl+C 后，localhost:8081 就无法访问。

### 第 2 步：访问首页

浏览器打开：

~~~text
http://localhost:8081/
~~~

预期：

~~~json
{
  "message": "hello from Kubernetes",
  "version": "一串 Git SHA"
}
~~~

### 第 3 步：检查健康接口

浏览器打开：

~~~text
http://localhost:8081/healthz
~~~

预期：

~~~json
{"status": "ok"}
~~~

也可以另开 PowerShell：

~~~powershell
Invoke-RestMethod http://localhost:8081/healthz
~~~

## 4. 登录 Argo CD

### 第 1 步：启动端口转发

另开 PowerShell：

~~~powershell
kubectl -n argocd port-forward svc/argocd-server 8080:443
~~~

保持该窗口打开。

### 第 2 步：获取解码后的密码

再开一个 PowerShell：

~~~powershell
$encoded = kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath="{.data.password}"
[Text.Encoding]::UTF8.GetString([Convert]::FromBase64String($encoded))
~~~

只执行第一行得到的是 Base64 编码，不能直接用于登录。

### 第 3 步：登录

浏览器打开：

~~~text
https://localhost:8080
~~~

填写：

~~~text
用户名：admin
密码：上一步第二行输出的密码
~~~

本地环境使用自签名证书。登录后选择应用 hello-k8s。

### 第 4 步：认识状态

| 状态 | 含义 |
|---|---|
| Synced | Git 配置和集群一致 |
| OutOfSync | Git 和集群不一致，等待同步 |
| Healthy | 应用健康 |
| Progressing | 正在部署或等待 Pod |
| Degraded | 应用异常，需要查日志和事件 |

正常状态是 Synced + Healthy。

## 5. 发布一个新版本

### 第 1 步：进入项目

~~~powershell
cd C:\Users\18231\Desktop\dd\hello-k8s-cicd
~~~

### 第 2 步：先拉取最新代码

~~~powershell
git pull --ff-only
~~~

预期是 Already up to date，或者显示下载了新的提交。

### 第 3 步：修改程序

打开 app.py，把：

~~~python
"hello from Kubernetes"
~~~

改成：

~~~python
"hello from version 2"
~~~

保存文件。

### 第 4 步：检查修改

~~~powershell
git status
git diff
~~~

确认只修改了自己需要修改的文件。

### 第 5 步：本地构建和测试

~~~powershell
docker build -t hello-k8s:test .
docker run --rm -p 18080:8080 hello-k8s:test
~~~

保持窗口打开，另开 PowerShell：

~~~powershell
Invoke-RestMethod http://localhost:18080/
Invoke-RestMethod http://localhost:18080/healthz
~~~

确认返回正确后，在运行容器的窗口按 Ctrl+C。

### 第 6 步：提交代码

~~~powershell
git add app.py
git commit -m "feat: release version 2"
git push
~~~

三个命令的作用：

| 命令 | 作用 |
|---|---|
| git add | 选择本次要提交的文件 |
| git commit | 创建本地版本记录 |
| git push | 把记录推送到 GitHub |

### 第 7 步：检查 GitHub Actions

1. 打开 GitHub 仓库。
2. 点击 Actions。
3. 点击最新的 ci-cd。
4. 等待状态变成绿色 Success。

流水线会自动：

1. 安装 Python 依赖。
2. 测试 /healthz。
3. 构建镜像。
4. 推送到 GHCR。
5. 将镜像 SHA 写入 k8s/deployment.yaml。
6. 自动提交 deployment.yaml。

红色失败时，点击红色步骤查看具体错误，不要反复 push。

### 第 8 步：检查部署

~~~powershell
kubectl -n argocd get application hello-k8s
kubectl -n hello rollout status deployment/hello-k8s
kubectl -n hello get pods
~~~

预期：

~~~text
Argo CD: Synced / Healthy
Deployment: successfully rolled out
Pod: 1/1 Running
~~~

### 第 9 步：验证新版本

如果应用端口转发没有运行，重新执行：

~~~powershell
kubectl -n hello port-forward svc/hello-k8s 8081:80
~~~

刷新：

~~~text
http://localhost:8081/
~~~

message 应变成 hello from version 2，version 应变成新的 Git SHA。

## 6. 查看状态和日志

查看 Pod：

~~~powershell
kubectl -n hello get pods -o wide
~~~

查看日志：

~~~powershell
kubectl -n hello logs <Pod名称>
~~~

持续查看日志：

~~~powershell
kubectl -n hello logs -f <Pod名称>
~~~

查看 Deployment：

~~~powershell
kubectl -n hello describe deployment hello-k8s
~~~

查看最近事件：

~~~powershell
kubectl -n hello get events --sort-by=.lastTimestamp
~~~

查看当前镜像：

~~~powershell
kubectl -n hello get deployment hello-k8s -o jsonpath="{.spec.template.spec.containers[0].image}"
~~~

## 7. 回滚

推荐使用 Git 回滚，因为 Git、Argo CD 和集群会保持一致。

### 第 1 步：查看历史

~~~powershell
git log --oneline --all
~~~

### 第 2 步：找到错误提交

示例：

~~~text
abc1234 feat: release version 2
def5678 feat: initial version
~~~

### 第 3 步：创建回滚提交

~~~powershell
git revert abc1234
git push
~~~

不要使用 git reset --hard。git revert 会保留完整审计记录。

### 第 4 步：等待自动部署

~~~powershell
kubectl -n hello rollout status deployment/hello-k8s
~~~

### 紧急回滚

~~~powershell
kubectl -n hello rollout history deployment/hello-k8s
kubectl -n hello rollout undo deployment/hello-k8s
~~~

紧急回滚后仍要修正 Git，否则 Argo CD selfHeal 会把集群恢复为 Git 中的版本。

## 8. 常见问题

### localhost:8081 无法访问

重新运行并保持窗口打开：

~~~powershell
kubectl -n hello port-forward svc/hello-k8s 8081:80
~~~

### ImagePullBackOff

~~~powershell
kubectl -n hello describe pod <Pod名称>
~~~

检查 GHCR 的 hello-k8s 包是否 Public，以及镜像地址是否正确。

### Argo CD OutOfSync

~~~powershell
kubectl -n argocd get application hello-k8s -o yaml
~~~

检查 repoURL、targetRevision、path 和 GitHub 网络。如果只是暂时网络超时，Argo CD 会自动重试。

### GitHub Actions 失败

进入 GitHub -> Actions -> 最新运行 -> 红色步骤。常见原因：

- Workflow YAML 缩进错误。
- Actions 没有 contents: write 或 packages: write 权限。
- GHCR 权限错误。
- 镜像名称包含大写字母。
- 测试没有通过。

### Argo CD 密码错误

必须执行两行解码命令，用户名固定为 admin。不要使用第一行返回的 Base64 字符串。

## 9. 最常用命令

~~~powershell
# 集群
kubectl get nodes

# 应用
kubectl -n hello get pods,service

# 访问应用
kubectl -n hello port-forward svc/hello-k8s 8081:80

# Argo CD 状态
kubectl -n argocd get application hello-k8s

# 发布
git add .
git commit -m "描述本次修改"
git push
~~~

## 10. 禁止事项

1. 不要把 GitHub 密码、Token、数据库密码提交到 Git。
2. 不要只用 latest 作为部署版本。
3. 正常发布不要直接 kubectl edit deployment。
4. 不要随意删除 argocd 和 hello namespace。
5. 不要把生产密钥写入 deployment.yaml。
